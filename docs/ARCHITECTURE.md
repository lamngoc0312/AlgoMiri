# AlgoMiri — Initial Architecture

## Strategy
Start with a modular frontend-only vertical slice, then add FastAPI and persistence behind interfaces. Avoid premature microservices and do not force a node-editor renderer onto every visual: SVG/React is appropriate for arrays; React Flow is useful for graphs, trees and conceptual solution maps.

## Shared domain concepts (TypeScript first; later mirrored in Python/Pydantic)
### ProblemSpec
`id`, `provider`, `providerId?`, `title`, `statement`, `constraints`, `examples`, `inputSchema`, `outputSchema`, `supportedStrategies[]`, `supportedVisualization`.

### SolutionStrategy
`id`, `problemId`, `name`, `intuition`, `timeComplexity`, `spaceComplexity`, `techniques[]`, `learningGraphId?`.

### SolutionGraph (conceptual, may be a DAG)
`nodes[]` (id, title, learningGoal, skills[], rationale), `edges[]` (source, target, reason), `strategyId`. This models the learner's reasoning; do not assume it equals the runtime execution graph.

### ExecutionStep (deterministic)
`id`, `stepIndex`, `action`, `line?`, `variables`, `visualState`, `highlightedIndices[]`, `explanation`, `isTerminal?`.
A trace is a list of immutable steps generated by a pure function of (strategy, validated input). React renders snapshots, it never invents algorithm transitions.

### LearningAttempt (future)
`userId`, `problemId`, `strategyId`, `startedAt`, `completedAt?`, `result`, `hintsUsed`, `predictionAccuracy?`, `selfRatedConfidence?`.

### SkillEvidence (future)
`skillId`, `attemptId`, `source`, `independenceLevel`, `success`, `recordedAt`. "Viewed visualization" alone must not count as mastery.

## MVP tracing architecture
1. UI validates input (array of finite safe integers, target integer, max length for smooth animation).
2. Pure brute-force and hash-map functions compute ordered `ExecutionStep[]` and result.
3. Timeline state manages selected strategy, current step, playback speed. Switching strategies resets position.
4. Canvas renders the selected `visualState` with clear labels / legend; text panel uses matching `explanation`.
5. Unit tests compare results with a simple correctness oracle and assert no inconsistent step indices.

## Multi-Problem Architecture (Sprint 4–6)
- **`ProblemModule<TInput, TVisual>` (`web/src/domain/core/types.ts`)**: Encapsulates a problem's `ProblemSpec`, strategies (variable count per problem), default input & presets, deterministic `generateTrace()`, conceptual `SolutionGraph`s, `ProblemLesson` (variable stage count, 3-level hints, progressive pseudocode), and dynamic `generatePrediction()`.
- **Discriminated Union `AnyVisualState`**: Uses `kind: 'array-hash' | 'stack' | 'bs-greedy'` rather than a single optional-field god object, allowing dedicated renderers (`VisualCanvas` for arrays/hash maps, `StackVisualCanvas` for vertical LIFO stacks, `CompositionVisualCanvas` for nested Driver + Subroutine composition) while sharing `useTracePlayback`, `PlaybackControls`, `WalkthroughPane`, `GuidedStagePanel`, `PredictNextStepCard`, and `SessionSummaryCard`.
- **`ProblemRegistry` (`web/src/domain/problems/registry.ts`)**: Central lookup powering `/problems` and `/studio/:problemId` (`two-sum`, `valid-parentheses`, `split-array-largest-sum`, with `/studio` redirecting to `/studio/two-sum`). Keying the Studio workspace by `problemModule.id` guarantees clean playback and learning state resets when switching problems.

## Conceptual SolutionGraph & Algorithm Composition Engine (Sprint 5–6)
- **Strict Separation from Runtime Execution & Validated Mapping:** A `SolutionGraph` is a conceptual DAG of reasoning subgoals (`input-model`, `invariant`, `operation`, `decision`, `technique`, `termination`) validated by `validateSolutionGraph()` (`web/src/domain/solutions/graphValidator.ts`). Trace steps may explicitly declare `conceptualNodeIds` (validated against the graph via `validateTraceNodeReferences()`), falling back to `mappedActions[]` when omitted, and never silently defaulting unrelated steps to the first node.
- **Implemented Composition Slice — Split Array Largest Sum (`web/src/domain/traces/splitArrayLargestSum.ts`):**
  - Models **Binary Search on Answer** (`role: 'driver'`) calling **Greedy Partitioning** (`role: 'subroutine'`) via explicit `CompositionContext` (`invocationId`, `bsIteration`, `role`).
  - Every child Greedy event (`greedy-start`, `greedy-add-to-group`, `greedy-new-group`, `greedy-result`) carries the exact `invocationId` (`bs-iter-k`) of the Binary Search iteration that initiated it, powering the interactive Binary Search Iteration Inspector without requiring a second playback engine.
  - Explicitly separates **O(1) auxiliary algorithm space** from the UI memory used to store immutable visualization snapshots.

## AI Boundary & FastAPI Backend (Sprint 7)
- **Server-Side Isolation (`api/`):** FastAPI exposes `GET /health`, `POST /api/analyze`, and `POST /api/tutor`. All LLM credentials (`GEMINI_API_KEY`) live strictly in server environment variables; the browser bundle never contains API secrets.
- **Untrusted Input Handling:** User-submitted statements are validated for size (`MAX_STATEMENT_CHARS`, `MAX_REQUEST_BODY_BYTES`), wrapped in `<untrusted_problem_statement>` tags with anti-injection instructions, and never logged in full.
- **Semantic Compatibility Routing (`api/app/routing.py`):** Evaluates semantics and constraint compatibility (`verified`, `ambiguous`, `conceptual_only`) before linking to a verified Studio engine — rejecting incompatible variants (e.g., 3Sum, Longest Valid Parentheses, negative-number Split Array) so unsupported problems never route to an unrelated deterministic engine.
- **Honest Offline Fallback:** When `GEMINI_API_KEY` is absent, `OfflineDemoProvider` returns `mode: "offline-demo"` with an explicit notice instead of faking a live AI call.
- **Strict Non-Fabrication Invariant:** Both `AnalyzeResponse` and `TutorResponse` enforce `verified_execution: False` and never emit `ExecutionStep[]` arrays.

## Security and legality
No secret values in client bundle or repo. No user-password request for coding sites. No automatic scraping of LeetCode statements. Respect provider metadata and rate limits. Treat pasted statements as user-owned private input; minimize logging and storage.
